## 2. Dataset Overview

This dataset contains simulated 2D particle trajectories from various anomalous diffusion models, organized into 10 evaluation instances for out-of-distribution (OOD) dynamics detection. Each instance defines a scenario where a set of in-distribution (ID) diffusion models must be distinguished from an OOD diffusion model.

The first five instances (`acfls_*`) use all five standard anomalous diffusion models (ATTM, CTRW, FBM, LW, SBM) as the ID set, paired with one of five additional dynamics (DBM, TSM, CBM, SINAI, OU) as OOD. The remaining five instances (`cfls_attm`, `afls_ctrw`, `acls_fbm`, `acfs_lw`, `acfl_sbm`) are cross-validation scenarios where one of the five standard models is held out as OOD and the remaining four serve as ID.

All trajectories have dimension m=2 and length w=50, with signal-to-noise ratios drawn from {1, 2, 10}. Training data is not provided; it must be generated using the `andi-datasets` Python package with the appropriate ID model configuration for each instance (30,000 samples per model category for training, 3,000 per category for validation).

## 3. File Formats & Schemas

### x_test.npy

- **Format**: NumPy binary (.npy), float64
- **Shape**: (N, 100) where N is `n_id_samples + n_ood_samples` (6000 for `acfls_*` instances, 5000 for cross-validation instances)
- **Content**: Each row is one 2D trajectory. The first 50 values are x-coordinates at time steps 1 through 50; the last 50 values are y-coordinates at time steps 1 through 50.

### instance_info.json

- **Format**: JSON
- **Fields**:
  - `n_id_samples` (int): Number of ID test samples
  - `n_ood_samples` (int): Number of OOD test samples
  - `n_total_samples` (int): Total test samples
  - `trajectory_dim` (int): Spatial dimension (always 2)
  - `trajectory_length` (int): Number of time steps (always 50)
  - `x_test_shape` (list): Shape of x_test.npy as [N, 100]
  - `id_models` (list of str): Names of the ID diffusion models for this instance
  - `n_id_models` (int): Number of ID models

## 4. Special Notes

- Training data must be generated by the solver using the `andi-datasets` Python package. Each instance requires generating trajectories for the specific set of ID models listed in `instance_info.json`, with parameters: dimension=2, length=50, SNR in {1, 2, 10}, 30,000 samples per model category for training and 3,000 per category for validation.
- The five `acfls_*` instances share the same ID model set and thus require the same training data configuration. Cross-validation instances each require a different training data configuration with only 4 ID models.
- Each trajectory in x_test.npy is individually Z-score normalized (zero mean, unit standard deviation per row).

## 5. Empirical EDA Addendum

All ten arrays agree with their JSON metadata. Each row contains 50 two-dimensional positions and is normalized to approximately zero mean and unit standard deviation.

| Instance group | Instances | ID / OOD rows per instance | Empirical trajectory summary |
|---|---|---:|---|
| Five standard ID models | `acfls_dbm`, `acfls_tsm`, `acfls_cbm`, `acfls_sinai`, `acfls_ou` | 5,000 / 1,000 | Median endpoint displacement 2.843–3.376; median path length 26.276–33.202 |
| One standard model held out | `cfls_attm`, `afls_ctrw`, `acls_fbm`, `acfs_lw`, `acfl_sbm` | 4,000 / 1,000 | Median endpoint displacement 3.130–3.183; median path length 28.575–29.014 |

Across instances, median tortuosity ranges from 7.876 (`acfls_dbm`) to 11.202 (`acfls_ou`). The OU scenario also has the largest median path length and lag-1 mean-squared displacement, making temporal and path-shape features more informative than endpoints alone. The visible files provide mixed test inputs and aggregate ID/OOD counts, not row-level labels; no assumption should be made that ID and OOD samples occupy contiguous or ordered blocks.
